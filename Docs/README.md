# 🧰 بستهٔ پرامپت ساخت «ویرایشگر و طراح G-code» برای ویندوز

این بسته برای سپردن پروژه به یک هوش مصنوعیِ کدنویس یا عامل برنامه‌نویسی آماده شده است. هدف، ساخت **برنامهٔ دسکتاپ قابل‌نصب روی Windows** است؛ نه وب‌سایت/PWA و نه برنامه‌ای که فایل را روی سرور بفرستد.

> **روش پیشنهادی:** همهٔ فایل‌های این پوشه را به عامل کدنویس بدهید. از او بخواهید `PROMPT_01_MASTER.md` را دستور اصلی قرار دهد و تمام مشخصات، پژوهش و fixtureهای دیگر را هم رعایت کند. اگر ابزار فقط یک متن می‌پذیرد، فایل‌ها را به ترتیب فهرست زیر به یک پیام پیوست/وارد کنید.

## 🥇 پشتهٔ فنی پیشنهادی در پرامپت

| گزینه | ارزیابی برای این پروژه |
|---|---|
| **Tauri 2 + Rust + React/TypeScript + Three.js + CodeMirror** | **انتخاب پیش‌فرض پیشنهادی:** برنامهٔ دسکتاپ واقعی، هستهٔ Rust برای parse/محاسبه، رابط گرافیکی کارآمد و دسترسی فایل محدودشده. UI داخل خود برنامه بسته‌بندی می‌شود؛ محصول نهایی وب‌سایت یا سرویس نیست. برای نصب بدون اینترنت باید WebView2 به روش آفلاین در installer بسته‌بندی شود؛ راهنمای رسمی Tauri روش `offlineInstaller` و `fixedRuntime` را توضیح می‌دهد: <https://v2.tauri.app/distribute/windows-installer/>. |
| **Electron + TypeScript + Chromium** | جایگزین مناسب اگر بسته‌بندی WebView2 در محیط هدف مشکل ایجاد کند یا runtime کاملاً همراه برنامه لازم باشد. نصب‌کننده معمولاً سنگین‌تر و مصرف RAM بیشتر است؛ امنیت preload/context isolation باید درست تنظیم شود. |
| **.NET 10 WPF** | گزینهٔ بومی Windows برای تیمی که اولویت اصلی‌اش کنترل‌های کاملاً native است یا پروژهٔ موجودش .NET است. برای editor + viewport سه‌بعدی پیچیده ممکن است توسعه/یکپارچه‌سازی بیشتری بخواهد؛ فقط با دلیل فنی جایگزین شود. |

**انتخاب عملی بسته:** Tauri 2 + Rust core + React/TypeScript + Three.js/WebGL2 + CodeMirror 6؛ خروجی NSIS `.exe` و در صورت امکان `.msi`؛ هدف Windows 10 22H2/Windows 11 x64. در مشخصات تأکید شده که نصب و استفادهٔ عادی باید با اینترنت قطع‌شده قابل انجام باشد. برای سیستم‌های آفلاین، prompt از عامل می‌خواهد روش WebView2 و trade-off حجم/به‌روزرسانی را با مستندات روز بررسی و در README ثبت کند.

## 🧭 ترتیب استفاده

1. `PROMPT_01_MASTER.md` را دستور اصلی بدهید.
2. تمام فایل‌های دیگر را هم به همان عامل بدهید؛ مخصوصاً مشخصات ویرایشگر، طراح، آزمون و پژوهش مرجع.
3. از عامل بخواهید **واقعاً فایل‌های پروژه را بسازد/تغییر دهد، installer ویندوزی تولید کند و آزمون‌ها را اجرا کند**؛ صرفاً طرح یا کد شبه‌واقعی تحویل ندهد.
4. اگر عامل مرور وب دارد، از او بخواهید منابع OGcode را طبق `PROMPT_03_OGCODE_INSPIRED.md` دوباره بررسی کند. اگر اپ کلید مجوز خواست، دسترسی را دور نزند و مورد را به‌عنوان محدودیت ثبت کند.
5. از عامل بخواهید تست نصب و اجرای بدون شبکه را انجام دهد یا، اگر محیط Windows آفلاین در اختیارش نیست، آن را صادقانه «اجرا‌نشده» گزارش کند.

## 🎯 دامنهٔ محصول در یک نگاه

- **ویرایشگر G-code:** بازکردن فایل محلی، نمایش کد و مسیر حرکتی کنار هم، توضیح هر خط، ویرایش، همگام‌سازی زنده و Save As با نام جدید.
- **طراح مارپیچی:** ساخت فرم چرخشی از منحنی مقطع، اعمال pattern هندسی و texture مسیر، تنظیم کف/پرینتر، شبیه‌سازی و خروجی STL/G-code.
- **نرم‌افزار ویندوزی و آفلاین:** نصب‌شونده روی سیستم خود کاربر؛ فایل‌ها و محاسبات محلی؛ بدون سرور، حساب کاربری، آپلود، CDN یا auto-update اجباری.
- **ایمنی چاپ:** نمایش سه‌بعدی G-code، مسیر نازل را بازسازی می‌کند و معمولاً مدل CAD اولیه را دقیق بازنمی‌سازد. هشدارهای مناسب لازم‌اند و چاپ فیزیکی تضمین نمی‌شود.

## ⚠️ نکتهٔ پژوهشی مهم

صفحهٔ عمومی OGcode و ویدئوی معرفی اطلاعاتی دربارهٔ گردش‌کار محصول می‌دهند، اما خود اپ روی دامنهٔ جداگانه است و صفحهٔ دسترسی آن کلید مجوز می‌خواهد. بنابراین پرامپت از عامل می‌خواهد منابع عمومی را بررسی کند، محدودیت‌ها را ثبت کند و ادعای دیدن بخش‌های قفل‌شده را نداشته باشد. یافته‌های اولیه در `OGCODE_REFERENCE_RESEARCH.md` آمده‌اند.
