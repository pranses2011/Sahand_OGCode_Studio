# ✅ مشخصات آزمون، ایمنی، امنیت و تحویل

این سند را به معیار پایان کار تبدیل کن. تست‌هایی که واقعاً اجرا نشده‌اند را موفق گزارش نکن.

## 1. هرم آزمون

| نوع آزمون | نمونهٔ پوشش |
|---|---|
| Rust unit | lexer، comments/checksum، حالت modal، محاسبهٔ E، قوس‌ها، الگوها، مش، output encoding |
| Frontend unit/component | انتخاب خط، نمایش inspector، undo/redo، خطاها، هشدار dirty state |
| Integration | import → parse → IR → preview mapping → edit → reparse → Save As |
| Desktop E2E | بازکردن برنامهٔ Tauri، native file dialog، import fixture، تغییر خط، مشاهدهٔ update، ذخیره در مسیر انتخابی |
| Performance | فایل بزرگ، thread/worker، چندبار import/dispose، re-render viewport و انتقال IPC |
| Offline/Installer | نصب‌کننده بدون اینترنت، اجرای برنامه با شبکه قطع، import/edit/save/export محلی |
| Manual | keyboard، RTL/LTR، DPI/اندازهٔ پنجره، بدون WebGL، پنجره‌های modal |

برای Rust از `cargo test` و برای frontend از Vitest استفاده کن؛ برای E2E از Playwright/WebdriverIO یا harness سازگار با Tauri که در repo قابل‌استفاده است. در صورت نبود ابزار، کمترین مجموعهٔ مناسب را اضافه و راه‌اندازی‌اش را مستند کن. تست‌های browser-only به‌تنهایی برای تحویل Windows کافی نیستند.

## 2. آزمون‌های پذیرش اجباری

### ویرایشگر G-code

- [ ] بارگذاری fixture بدون تغییر متن خام؛ حفظ commentها، blank lineها و line ending.
- [ ] نمایش درست حرکت X/Y/Z و تفکیک extrusion از travel.
- [ ] رفتار درست در جابه‌جایی بین `G90/G91`، `M82/M83`، `G20/G21` و `G92`.
- [ ] retract در E مطلق و نسبی با حرکت چاپی اشتباه نشود.
- [ ] قوس معتبر `G2/G3` با plane پشتیبانی‌شده به path تبدیل شود؛ arc نامعتبر diagnostic بسازد.
- [ ] فرمان دما/فن state را تغییر دهد اما segment هندسی جعلی نسازد.
- [ ] comment شامل متن شبیه command اجرا نشود.
- [ ] parser فرمان ناشناخته را حفظ و علامت‌گذاری کند؛ خطای آن سایر خطوط را بی‌دلیل حذف نکند.
- [ ] انتخاب خط، segment و توضیح را همگام کند؛ خط غیرحرکتی پیام توضیحی درست نشان دهد.
- [ ] ویرایش متن، parsing و preview را همگام کند؛ parser error متن تایپ‌شده را پاک نکند و preview قدیمی را مشخص کند.
- [ ] undo/redo، reset line و dirty state درست باشند.
- [ ] Save As نام جدید بسازد و فایل مبدأ تغییر نکند.
- [ ] checksum/line number پس از edit یا با سیاست معتبر دوباره ساخته شوند یا با هشدار و تأیید کنار گذاشته شوند.
- [ ] فایل بزرگ در thread غیرمسدودکنندهٔ Rust یا worker مناسب parse شود، رابط پاسخ‌گو بماند و لغو کار ممکن باشد.

### طراح مارپیچی

- [ ] منحنی/پروفایل پایه از نقطه‌ها ساخته و در 3D دیده شود.
- [ ] تغییر ارتفاع/قطر/تعداد تکرار، هندسه و bounds را واقعاً تغییر دهد.
- [ ] pattern هندسی در mesh و STL موجود باشد.
- [ ] texture مسیر را تغییر دهد و اثر آن در toolpath/G-code دیده شود؛ در STL به‌عنوان ذخیره‌نشده توضیح داده شود.
- [ ] floor انتخابی در نمای مسیر و خروجی G-code سازگار باشد.
- [ ] nozzle/build volume/profile روی حداقل یک validation واقعی اثر بگذارد.
- [ ] preview و G-code از Toolpath IR مشترک باشند؛ مختصات چند segment با هم تطبیق داده شوند.
- [ ] فایل STL تولید شود و با parser/validator مستقل یا آزمون داخلی ساختار آن بررسی شود.
- [ ] JSON پروژه ذخیره و reload شود؛ schema خراب/نسخهٔ ناشناخته پروژهٔ جاری را نابود نکند.
- [ ] انتقال خروجی طراح به ویرایشگر با متن واقعی G-code کار کند.
- [ ] هیچ قابلیت چنددیواره، infill یا top solid ادعا نشود مگر واقعاً پیاده‌سازی و آزموده شده باشد.

### UX / سازگاری

- [ ] کل گردش‌کار اصلی با keyboard قابل انجام باشد.
- [ ] RTL فارسی و کد LTR در WebView2 ویندوز خراب نشوند.
- [ ] در پنجرهٔ کوچک یا DPI بالا، انتخاب/ویرایش/نمایش preview قابل استفاده بماند.
- [ ] با WebGL غیرفعال، پیام راهنما و قابلیت‌های متنی همچنان کار کنند.
- [ ] هیچ دکمهٔ بی‌اثر، placeholder، `TODO` یا دادهٔ نمونهٔ پنهان به‌عنوان قابلیت نهایی وجود نداشته باشد.

### نصب و اجرای کاملاً آفلاین Windows

- [ ] نصب‌کنندهٔ NSIS `.exe` واقعی بساز؛ در صورت امکان `.msi` هم بساز.
- [ ] حالت WebView2 در Tauri طوری تنظیم شود که نصب روی سیستم فاقد runtime هم بدون اینترنت انجام‌پذیر باشد؛ برای این نیاز از bootstrapper آنلاین استفاده نکن.
- [ ] نصب را در Windows 10/11 x64 یا VM تمیز، با شبکه قطع و بدون runtime از پیش نصب‌شده امتحان کن؛ اگر این محیط واقعاً در دسترس نیست، مورد را اجرا‌نشده ثبت کن.
- [ ] پس از نصب، برنامه با firewall/network غیرفعال باز شود و import، parse، 3D preview، edit، Save As، save/load پروژه و export STL/G-code کار کنند.
- [ ] با ابزار مناسب، نبود درخواست خروجی به اینترنت را در زمان اجرای قابلیت‌های اصلی تأیید کن؛ برنامه server محلی هم باز نکند.
- [ ] هیچ remote font/CDN/API/login/telemetry/auto-update لازم نباشد؛ همهٔ UI و help داخل package باشند.
- [ ] installer به‌طور پیش‌فرض برای نصب per-user کار کند و بدون admin اجرا شود، مگر اینکه انتخاب system-wide مستند شده باشد.
- [ ] نصب، uninstall و reinstall را بررسی کن؛ uninstall نباید G-code یا پروژه‌های کاربر را حذف کند.
- [ ] README شامل اندازهٔ نصب‌کننده، نیازمندی دقیق Windows، روش نصب آفلاین، runtime mode و روش build باشد.

## 3. آزمون ایمنی و ریسک G-code

- نرم‌افزار **G-code را اجرا نکند و به printer وصل نشود**.
- دستورات خطرناک/حساس مثل توقف اضطراری، تغییر دما، حرکت خارج از bounds، unknown homing/profile، فرمان پاک‌کردن یا ماکروی ناشناخته شناسایی/هشدار داده شوند، در حدی که قابل‌تشخیص‌اند.
- دما، feedrate، nozzle و build volume فقط وقتی حد دارند که profile تعریف کرده باشد؛ مقادیر استاندارد جهان‌شمول جعل نکن.
- preflight خروجی، warningهای قابل‌اقدام را پیش از ذخیره نشان دهد؛ Save As را با preview نتیجه و تأیید کاربر انجام بده.
- متن هشدار پیشنهادی: «این برنامه صحت چاپ فیزیکی را تضمین نمی‌کند. فایل را با ابزار/سازندهٔ معتبر بررسی کنید و اولین چاپ را زیر نظر داشته باشید.»
- هیچ متن بازاریابی مانند «کاملاً امن»، «بدون خطا» یا «آمادهٔ چاپ برای هر دستگاه» استفاده نکن.

## 4. امنیت و حفظ داده

- فایل G-code ورودی دادهٔ غیرفعال است: آن را `eval` نکن، به shell نفرست، در iframe اجرا نکن و از دستورهای داخل آن برای فراخوانی network استفاده نکن.
- محتوای فایل را در UI با `innerHTML` قرار نده؛ از text rendering امن استفاده کن.
- نام فایل، commentها و متن پروژه را untrusted input بدان؛ در export/path traversal یا injection اجازه نده.
- capabilityهای Tauri را حداقلی تنظیم کن؛ فایل فقط از مسیرهای انتخاب‌شده با دیالوگ native خوانده/نوشته شود؛ plugin shell و اجرای command عمومی نداشته باش.
- از threadهای Rust/Web Worker و منابع WebGL به‌درستی استفاده و آن‌ها را آزاد کن؛ limit/guard برای طول خط، تعداد segment و عدد NaN/Infinity داشته باش.
- نشت محتوای فایل به telemetry/log/analytics ممنوع؛ در زمان اجرای اصلی درخواست شبکه/سرور محلی نداشته باش.
- dependencyهای جدید را بررسی و دلیلشان را ثبت کن؛ از CDN لازم برای اجرای برنامه استفاده نکن.

## 6. قالب گزارش نهایی عامل کدنویس

در پایان به فارسی با این قالب گزارش بده:

1. **وضعیت:** کامل / کامل با محدودیت / ناقص.
2. **قابلیت‌های ساخته‌شده:** بر اساس دو ماژول.
3. **فایل‌ها/معماری مهم:** مسیرهای دقیق.
4. **روش نصب و اجرا:** دستورهای واقعی و نتیجه.
5. **آزمون‌ها:** نام، تعداد، موفق/ناموفق/اجرا‌نشده؛ فقط خروجی واقعی.
6. **پژوهش OGcode:** چه منابعی واقعاً بررسی شد و کدام‌ها در دسترس نبودند.
7. **محدودیت‌ها و ریسک‌ها:** dialectهای پشتیبانی‌نشده، arcها، profileها، سازگاری Windows/WebView2، حجم installer و performance.
8. **قبل از چاپ:** هشدار ایمنی روشن.

اگر build یا test شکست خورد، ابتدا تا حد ممکن مشکل را برطرف کن و دوباره اجرا کن؛ شکست را پنهان نکن.
